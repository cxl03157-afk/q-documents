### README の方針（8/19 決定・別Issueで着手）

**読み手は職業訓練校の講師**。このアプリも製造業の品質文書も開発の経緯も知らない前提で書く。
**`S-3`・`F-11`・`PR #32` のような内部の記号を使わない。**

**最重要の制約: 講師は公開URLにアクセスできない**（社内IP制限が要件のため他IPからは403）。
**動くことを示せるのは動画とスクリーンショットだけ**なので、その説明を README の先頭近くに置く。

構成は13章（これは何か／デモ／解決した課題／できること／使い方／システム構成／
**設計で判断したこと**／セキュリティ／コスト／品質の担保／実運用時の課題／開発の進め方／セットアップ）。
**評価の中心は「設計で判断したこと」**で、状態遷移を非同期処理1か所に閉じた理由・
ストレージクラスの3段階・IP制限を入口ごとに分けた理由・文書番号を末尾から解析する理由・
リビジョンアップを「最新」からのみ許す理由・役割単位の合言葉とその限界、から5〜6点に絞る。

**実体験の書き方**: 文書管理がエクセルの手作業で、**採番ミスや旧版の誤使用があった程度に留める**
（利用者の指示。業種・工程名は伏せる）。**言語は日本語のみ。**
